# 滑动窗口 vs 动态规划：怎么选？

## 一、先看这道题的本质特征

「无重复字符的最长子串」有三个关键词：

- **子串**（连续，不是子序列）
- **最长**（求极值）
- **不重复**（一个可判断的"合法性"条件）

这三个特征叠加，几乎就是滑动窗口的"身份证"。

---

## 二、判断用滑动窗口还是 DP 的核心标准

| 维度        | 滑动窗口                                        | 动态规划                    |
| --------- | ------------------------------------------- | ----------------------- |
| **问题形态**  | 求连续区间的极值/计数，且区间合法性可单调判断                     | 求最优子结构，决策依赖前面多个状态       |
| **收缩方向**  | 右指针扩展时，左指针**只能往右走**（**单调**）                 | 状态转移可能回头看任意位置           |
| **合法性判断** | 加入一个新元素后，能快速判断"是否合法"，不合法就收缩左边               | 没有这种"窗口合法/不合法"的二分性质     |
| **典型问法**  | "最长/最短子串满足XX条件"、"至多包含K个XX"、"和≥target的最短子数组" | "最长递增子序列"、"编辑距离"、"背包问题" |

**一句话判断法**：如果右指针往右走时，左指针永远不需要往左退（单调性成立），就用滑动窗口；如果每个位置的答案依赖于前面任意位置的最优解，就用 DP。

---

## 三、为什么这题不用 DP？

Krahets 的题解里提到了 DP 思路，但滑动窗口更优。原因：

- DP 状态 `dp[i]` 表示以 `s[i]` 结尾的最长无重复子串长度，转移时需要知道上一次重复字符的位置——这本质上还是在维护一个"窗口"的左边界。
- 既然左边界是单调右移的，直接用双指针维护窗口比开 DP 数组更直观、空间更省。

---

## 四、滑动窗口通用思考框架（五连鞭）

Eason 总结的模板非常实用，核心五步：

```
Step 1: 定义需要维护的变量
        → 最大/最小长度、和、哈希表（计数）

Step 2: 定义窗口首尾端 (start, end)，然后滑动
        → for end in range(n):

Step 3: 进入新元素时，更新维护变量
        → 计数+1、累加和、尝试更新答案

Step 4: 判断窗口是否合法
        → 固定窗口：用 if，左指针匀速右移
        → 可变窗口：用 while，不合法就不断收缩左边

Step 5: 返回答案
```

**关键在 Step 4 的二选一**：

- 窗口长度**固定**（如"长度为K的子数组最大和"）→ `if`
- 窗口长度**可变**（如本题、"和≥target的最短子数组"）→ `while` 收缩到合法为止

---

## 五、快速自检：拿到一道题问自己三个问题

1. **求的是连续区间吗？** 
	1. 是 → 可能滑动窗口；
	2. 否（子序列/任意组合）→ 大概率 DP
2. **右指针扩展时，左指针能单调移动吗？** 
	1. 能 → 滑动窗口；
	2. 不能 → DP
3. **"合法/不合法"能在 O(1) 或 O(Σ) 判断吗？**
	1. 能 → 滑动窗口效率高；
	2. 不能 → 考虑 DP 或其他

记住：滑动窗口的灵魂是**单调性**，DP 的灵魂是**最优子结构+重叠子问题**。两者不互斥（有些题两种都能解），但选对了写起来事半功倍。
