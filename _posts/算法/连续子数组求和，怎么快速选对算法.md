# 核心思路拆解：连续子数组求和，怎么快速选对算法

## 1. 先回答两个最大疑问：滑动窗口为什么不行，能不能排序？

> 直觉：连续子数组 → 滑动窗口 ✅ 这个直觉**一半对一半错**： 滑动窗口只适合：**窗口区间和具有单调性**，也就是数组全部是非负数（≥0）。

- 全非负：右指针右移，区间和一定变大；左指针右移，区间和一定变小，可以伸缩窗口来找目标和。
- 本题存在**负数**：窗口增加一个负数，总和反而变小，**失去单调性**。窗口变大，和可增可减，没办法确定左指针该往哪移动，滑动窗口失效。

❌ **绝对不能排序！** 题目要求**子数组，是原数组里连续一段，不能打乱元素顺序**。一旦排序，元素位置就变了，连续的定义直接破坏，得到的是子序列，不是子数组。

> 划重点：**子数组=原数组连续片段，不能排序；子序列才可以不连续**。

## 2. DP思路为什么会爆内存（二维DP）

想法：`dp[i][j]` 代表`i~j`区间和，`dp[i][j] = dp[i][j-1]+nums[j]`，这个递推关系数学上没问题。
- 时间复杂度：$O(n^2)$，n=2e4时，$4\times10^8$次运算，直接超时
- 空间复杂度：$O(n^2)$，二维数组，n=2e4 根本存不下，直接超出内存限制，也就是你提交遇到的`超出内存限制`。

DP这个思路**逻辑成立，但不适合本题的数据规模**。

> 启示：区间DP适合n很小（一般n≤1000），一旦n上万，二维DP基本直接报废。

## 3. 建立一个通用记忆：**连续子数组求和问题 → 优先想到前缀和**

公式： $$sum(i,j)=pre[j+1]-pre[i]$$ `pre[0]=0，pre[x]`是数组前x个元素的累加和。 **任何一段连续子数组的和，都可以转化成两个前缀和的差值**。这是一个万能转换，只要求连续一段的和，都可以写出这个式子。

问题转化：找到多少对`i<j`，满足 $pre[j]-pre[i]=k$，变形： $$pre[i]=pre[j]-k$$

> 翻译：遍历每一个`pre[j]`，问**在j之前，pre数组里面有多少个值等于`pre[j]-k`**。

## 4. 怎么把两次遍历合并，降低复杂度（前缀和+哈希优化）

朴素前缀和：先完整算出pre数组（第一次遍历），再二重循环枚举所有i,j（$O(n^2)$）。
优化点：
1. 不需要**完整保存整个pre数组**；我们只需要**已经遍历过的前缀和，以及它出现多少次**。
2. 边遍历数组，边实时计算当前前缀和`pre_j`；
3. 在计算`pre_j`之后，立刻查询哈希表里`pre_j -k`的计数，加到答案；
4. 再把当前`pre_j`存入哈希表，留给后面的元素查询。
👉 一次遍历完成，时间$(O(n))$，空间$(O(n))$。

> 顺序不能颠倒：**先查，再存入哈希表**。防止把当前j自己算进去（i必须小于j）。 初始化哈希表`{0:1}`：处理子数组从数组开头就开始的情况，比如`nums=[1],k=1`，`pre_j=1`，查找`1-1=0`。

# 一套思考流程（以后遇到连续子数组求和直接套用）

1. 看到**连续子数组 + 求和** → 立刻写出前缀和公式 $sum(i,j)=pre[j]-pre[i]$
2. 判断数组元素有没有负数：
    - 全部≥0：可以尝试滑动窗口
    - 存在负数：**放弃滑动窗口**，前缀和路线
3. 看数据规模：
    - n很小（n<1000）：暴力/区间DP都可以
    - n上万：$O(n^2)$算法会超时，必须优化；观察公式，是否可以用哈希表统计前面值的出现次数
4. 对式子做代数变形，把「求差值等于k」变成「查找前面某个值的出现次数」，类似两数之和思想。

# 容易踩坑总结

1. 子数组**不能排序**，排序破坏连续性；
2. 滑动窗口依赖单调性，负数存在直接失效；
3. 二维区间DP只适合小规模数据，大数据直接内存爆炸；
4. 哈希表初始化`pre=0，次数1`是高频坑；
5. 顺序：**先查询答案，再更新哈希表**。

## 三、易错笔记【高频踩坑点】

### 🔴 易错点 1：忘记初始化前缀和 `s[0]=0`

代表**0 个元素的前缀和等于 0**，哈希表初始 `cnt[0]=1`

- 错误例子：`nums=[1],k=1`，不加`cnt[0]=1`，答案得到 0，正确是 1

> 原理：子数组从数组头部开始时 \(s[j]-s[0]=k\)，s [0] 必须存在

### 🔴 易错点 2：`先更新哈希，再算ans` 顺序颠倒

```
# ❌ 错误写法
cnt[s] +=1
ans += cnt[s-k]
# ✅ 正确写法
ans += cnt[s-k]
cnt[s] +=1
```

顺序颠倒会**把当前 s 算进查找范围**，当 k=0 时，会把当前单个前缀和误统计，造成重复计数

### 🔴 易错点 3：看到子数组就想用滑动窗口

> 滑动窗口**仅适合数组全部非负数**！ 一旦存在负数，窗口和不单调，左指针不知道该左移还是右移，560 直接滑窗会 WA。

### 🔴 易错点 4：混淆「子数组」和「子序列」

- **子数组：连续** → 前缀和 / 滑窗
- **子序列：可以不连续** → DP（比如零钱、最长递增子序列） 很多人读题直接忽略 “连续”，解法完全跑偏

### 🔴 易错点 5：哈希表 value 存错东西

- 求**子数组个数**：value = 该前缀和出现次数
- 求**最长子数组**：value = 该前缀和**第一次**出现的下标（不要覆盖！）
- 求**最短子数组**：value = 该前缀和**最近一次**出现的下标（不断覆盖更新）

### 🔴 易错点 6：前缀和溢出（Python 不用关心，C++/Java 注意）

本题 Python 无溢出问题，其他语言需要考虑 int 范围。

### 🔴 易错点 7：k 可以是负数，不要做提前过滤

题目中 \(-10^7 \le k \le 10^7\)，不要默认 k>0。

## 四、母题 560 最简模板（可直接背诵）

```
from collections import defaultdict
class Solution:
    def subarraySum(self, nums, k: int) -> int:
        cnt = defaultdict(int)
        cnt[0] = 1
        pre_sum = 0
        ans = 0
        for num in nums:
            pre_sum += num
            ans += cnt[pre_sum - k]
            cnt[pre_sum] += 1
        return ans
```
