## 用于支撑平台判断一份资产是否值得继续被分发

---

## 1. 概述与目标

### 1.1 背景

WorkBuddy 平台内存在 agents、skills、plugins、tools 等多种资产。当前分发体系过度依赖热度、下载量等结果性指标，导致少数头部资产占据大部分流量，形成马太效应；大量质量尚可的长尾资产无法有效触达用户，生态多样性和创作者积极性受损。

核心问题不是长尾资产没有价值，而是平台缺少一套**可信、可量化、可解释的质量评估体系**，以及与之配套的**反马太分发干预机制**。同时，任何评估与干预措施本身都有成本，必须在评估精度、用户体验、工程资源和运营投入之间做出权衡。

### 1.2 框架目标

本框架旨在为平台提供一套统一的资产质量评估与分发决策依据，具体目标：

1. 建立多维度、细粒度的资产质量评估体系，覆盖平台内主要资产类型。
2. 用量化指标与证据链回答：**一个资产是否值得继续被分发？如果值得，应加权还是正常分发？如果不值得，应降权、观察还是下架？**
3. 打破纯热度导向的马太效应，识别并扶持低曝光但高质量的长尾资产。
4. 通过新手保护、不确定性探索、动态加权等机制，让流量分配回归“真实价值”与“用户需求”的匹配。
5. 保证评估过程可解释、可审计、可申诉，形成平台、创作者、用户三方信任。
6. 在实现上述目标的同时，**控制评估与干预的总成本**，避免过度投入导致系统臃肿、创作者疲惫或用户体验受损。

### 1.3 适用范围

本框架适用于平台内所有可被分发的资产类型，包括但不限于：

- Agent
- Skill
- Plugin
- Tool
- Prompt 模板
- 工作流/流程资产

不同资产类型可在维度权重和阈值上做适配，但核心评估逻辑保持一致。

---

## 2. 核心原则

| 原则 | 说明 |
|---|---|
| 多维度细粒度 | 不只看使用量或评分，综合静态质量、执行质量、用户体验、安全合规等。 |
| 真实反馈动态驱动 | 质量分随用户真实行为、评价、投诉动态更新，而非一次性审核。 |
| 可解释可审计 | 每个分数都能下钻到具体证据，所有阈值、权重、口径可版本化管理。 |
| 小样本保守处理 | 新资产或样本不足时，使用收缩估计，避免误判。 |
| 分级准入 | 不同质量分对应不同分发权重，阈值公开透明。 |
| 反马太干预 | 在质量门槛内引入多样性、潜力加权和冷启动探索流量。 |
| 一票否决 | 安全、合规、隐私问题可直接下架，不依赖综合分。 |
| 动态校准 | 阈值基于平台分位数动态调整，避免一刀切。 |
| **成本效能意识** | **评估精度、评估频率、探索流量均按资产重要性和决策需要分级，避免“一刀切”的过度投入。** |

## 3. 评估维度与量化指标

评估框架分为 8 个维度，每个维度包含细粒度指标。权重可配置，以下为建议初始权重。

| 维度 | 建议权重 | 细粒度指标 | 数据来源 |
|---|---|---|---|
| A. 资产基础质量 | 10% | 字段完整度、描述与功能一致性、版本规范性、示例覆盖率、文档完整度 | 元数据检查、LLM/人工审核 |
| B. 功能与执行质量 | 25% | 任务成功率、首次成功率、平均执行时长、错误率、超时率、输出格式合规率 | 运行日志、任务执行记录 |
| C. 用户体验质量 | 25% | 用户评分、满意度、NPS、重复使用率、收藏率、投诉率、主动分享率 | 用户反馈、行为埋点 |
| D. 分发与场景匹配效率 | 15% | 曝光-点击率、点击-使用率、使用-完成率、场景匹配准确率、跨场景失败率 | 分发日志、推荐埋点 |
| E. 稳定性与可维护性 | 10% | 可用性 SLA、P95 延迟、近 30 天事故次数、版本迭代频率、依赖脆弱性 | 监控系统、版本记录 |
| F. 安全与合规 | 10% | 权限最小化程度、敏感数据访问、安全扫描漏洞数、合规违规记录 | 安全扫描、权限审计 |
| G. 创作者信用 | 5% | 创作者历史资产平均质量、违规记录、维护响应时效、被采纳改进率 | 平台历史数据 |
| H. 长尾潜力与多样性 | 调节项 | 曝光-质量偏差、覆盖任务类型数、低曝光高完成率、对长尾用户群覆盖度 | 分发数据、用户画像 |

说明：

- H 维度作为**调节项**，不直接计入综合分，但用于识别“潜力资产”和反马太加权。
- 不同资产类型可调整维度权重。例如 tools 更看重稳定性和安全；prompt/skill 类更看重场景匹配与用户满意度。
- 所有指标必须有统一埋点、统一口径，变更需发布说明。

## 4. 质量分计算与置信度

### 4.1 综合质量分 QS

```
QS = Σ(w_i × subscore_i)  ，范围 0–100
```

每个子分 `subscore_i` 必须包含：

- 原始指标值
- 标准化后的 0–100 分
- 样本量
- 置信度
- 时间窗口

### 4.2 小样本处理

对评分类、成功率类指标，采用 **Wilson 下界** 或 **贝叶斯平均** 进行收缩：

```
收缩分 = (n × 资产均值 + k × 平台先验均值) / (n + k)
```

当样本量 n < 30 时，质量分置信度较低，分发策略应保守处理，但仍保留探索流量。

### 4.3 输出形式

每个资产的质量评估结果不只是单一分数，而是：

```
QS = 78 / 100
95% CI：[74, 82]
置信度：0.72
样本量：使用 120 次，用户 68 人，评分 43 条
近 30 天趋势：+3.2
```

### 4.4 分场景质量分

同一资产在不同任务场景下可能表现差异很大。系统应支持：

> 全局质量分 + 场景质量分矩阵

分发时优先使用场景分，避免“全局高分资产霸占所有场景”。

## 5. 准入与分级阈值

基于质量分将资产分为 5 个等级，阈值建议基于平台分位数动态校准。

| 等级 | 条件 | 分发策略 |
|---|---|---|
| 冷启动/待评估 | 样本不足或置信度 < 0.6 | 限制分发，但保留探索流量 |
| 正常分发 | QS ≥ 60，置信度 ≥ 0.6，安全合规通过 | 正常进入推荐候选池 |
| 优质加权 | QS ≥ 80，置信度 ≥ 0.7，近 30 天无事故/投诉异常 | 推荐加权，优先展示 |
| 降权观察 | QS 40–60，或关键维度低于阈值 | 流量减半，通知创作者整改 |
| 下架/复审 | QS < 40，或触发一票否决项 | 停止分发，进入复审流程 |

**一票否决项**：

- 安全漏洞高危
- 隐私违规
- 恶意行为
- 严重内容违规
- 刷分/刷量实锤

## 6. 动态更新机制

### 6.1 实时行为接入

用户行为事件实时进入评估管道：

```
曝光 → 点击 → 使用 → 成功/失败 → 评分/投诉/收藏
```

每条事件更新对应子分，并触发综合分重算。

### 6.2 冷启动机制

新资产进入平台后：

1. 静态质量预审，得到基础分；
2. 给予 5%–10% 的探索流量；
3. 达到最小样本量（如 30 次使用、20 个独立用户）后，质量分置信度提升；
4. 根据真实表现进入正常分发或降权池。

### 6.3 时间衰减

近期反馈权重更高，建议使用指数加权：

```
score_t = α × score_recent + (1-α) × score_old
```

例如 30 天窗口权重 0.7，90 天窗口权重 0.3。

### 6.4 触发式重算

以下情况触发即时重算或复审：

- 资产发布新版本
- 事故/投诉激增
- 安全扫描发现新漏洞
- 连续 30 天无维护且错误率上升
- 创作者发起申诉

## 7. 反马太分发干预机制

在质量评估基础上，通过主动干预分发策略，打破“强者恒强”的马太效应。

### 7.1 曝光-价值动态加权

每个资产在分发系统中拥有一个**动态价值分 V**：

```
V = α × 质量分(QS) + β × 场景匹配分 + γ × 多样性贡献 + δ × 潜力因子
```

- **质量分(QS)**：来自质量评估框架，包含置信度。
- **场景匹配分**：根据当前用户任务上下文计算，确保推荐相关性。
- **多样性贡献**：该资产在当前推荐列表中与其他资产的差异度，避免同质化。
- **潜力因子**：对低曝光但高质量、或高不确定性的资产给予额外加权。

权重 α,β,γ,δ 可配置，并可根据业务目标动态调整。

**动态调整规则**：

- **热度惩罚**：当资产曝光量超过一定阈值（如平台总曝光的 5%），其曝光权重乘以衰减系数 `decay = 1 / (1 + log(曝光量/阈值))`。
- **曝光矫正**：对于质量分高于平台均值但曝光低于应有水平的资产（曝光-质量偏差为正），给予曝光补偿系数。
- **场景内公平竞争**：同一场景下，优先保证场景匹配分高的资产，但也要保证每个场景下至少有 N 个不同创作者的资产进入候选池。

每次加权调整都记录在案，运营和创作者可以看到：

> “资产 X 因曝光-质量偏差 +15%，获得 1.2 倍曝光加权；资产 Y 因曝光量超过阈值，曝光权重衰减 0.8 倍。”

### 7.2 新手保护期

新发布的资产（或新入驻创作者的首个资产）自动进入**新手保护期**，建议时长 14–30 天。

保护期内规则：

- **最低曝光保底**：每天获得一定量的基础曝光（如 50–100 次展示）。
- **独立评估通道**：保护期内质量分暂时不与全量老资产直接竞争排序，而是通过“保护期专属流量池”进行验证。
- **保护期流量上限**：保护期资产整体曝光不超过平台总曝光量的 5%–8%。

保护期结束时：

- 若置信度达到阈值，进入正常分发池，按动态价值分参与竞争。
- 若样本不足但质量分预估良好，可延长保护期或给予“半保护”状态。
- 若质量分低于下限或触发一票否决，直接下架或降权观察。

防止滥用：

- 同一创作者短期内大量发布低质资产，保护期流量自动缩减。
- 保护期资产若用户投诉率高或完成率极低，可提前终止保护期并降权。

### 7.3 不确定性驱动的探索曝光

对于新资产或样本量不足的资产，其质量分置信度低，主动给予探索曝光可以快速降低不确定性。

**策略**：借鉴多臂老虎机（MAB）中的汤普森采样或置信区间上界（UCB）思想：

- 对每个资产维护质量分的后验分布。
- 推荐时从每个资产的后验分布中采样一个值，按采样值排序。
- 不确定性高的资产采样值波动大，有一定概率获得更高排名，从而获得曝光。

简化规则：

```
探索概率 = f(置信度, 样本量)
```

例如：

- 样本量 < 10：探索概率 30%
- 样本量 10–30：探索概率 15%
- 样本量 30–100：探索概率 5%
- 样本量 > 100：探索概率 1%

**预算控制**：设置全局探索流量预算，例如占总曝光量的 10%–15%。探索流量优先分配给通过基础质量门槛（如静态质量分 ≥ 60）且置信度低的资产。

### 7.4 多样性约束与长尾保护

- **创作者维度**：同一创作者的资产在单次推荐列表中不超过 2 个。
- **资产类型/标签维度**：单次推荐中，某一细分类型资产占比不超过 30%。
- **相似度约束**：用 MMR（最大边际相关性）算法，在相关性和多样性之间平衡。
- **长尾曝光保底**：每天从“低曝光但质量分 ≥ 阈值”的资产池中随机抽取一定比例，进入当天推荐候选池。
- **反垄断阈值**：单个资产曝光占平台总曝光比例不得超过 5%；单个创作者所有资产曝光合计占比不得超过 15%。超过阈值后自动触发曝光衰减。

### 7.5 分发决策引擎

最终分发建议由质量评估结果与反马太策略共同决定。决策流程如下：

1. 资产是否触发一票否决？→ 是 → 下架/复审。
2. 资产是否处于新手保护期？→ 是 → 按保护期规则分配基础曝光 + 探索流量。
3. 资产置信度是否不足？→ 是 → 进入探索池，按探索概率获得曝光。
4. 资产质量分是否达到正常分发阈值？→ 否 → 降权观察或下架。
5. 资产是否达到优质加权条件？→ 是 → 进入优质加权池。
6. 计算动态价值分 V，结合多样性约束和反垄断阈值，生成最终排序和分发建议。

决策输出示例：

```
资产 A：QS 82，置信度 0.75，场景匹配 0.9，曝光-质量偏差 +12%
→ 建议：优质加权，曝光加权 1.3 倍，进入推荐候选池前 20%。

资产 B：QS 58，置信度 0.8，投诉率 4%
→ 建议：降权观察，流量减半，通知创作者整改。

资产 C：QS 45，置信度 0.5，样本量 8
→ 建议：保留探索流量，暂不进入正常分发，等待数据积累。
```

## 8. 成本与效能权衡机制

### 8.1 成本分类与预算

评估与干预机制本身会产生以下成本：

| 成本类型 | 说明 | 控制手段 |
|---|---|---|
| 计算与工程成本 | 实时事件管道、质量分重算、场景分矩阵存储与计算 | 分层评估策略、批量处理、缓存、采样 |
| 用户体验成本 | 探索流量可能推送不成熟资产，导致任务失败或满意度下降 | 探索流量预算、探索代价上限、质量门槛 |
| 运营与人工成本 | 人工抽检、申诉处理、创作者沟通 | 自动化优先、抽检比例控制、申诉流程简化 |
| 创作者维护成本 | 频繁评估、降权通知、整改要求增加创作者负担 | 评估频率自适应、稳定资产降低打扰 |

### 8.2 分层评估策略

根据资产状态和重要性，采用不同的评估精度和频率：

| 资产状态 | 评估精度要求 | 评估频率 | 实现方式 |
|---|---|---|---|
| 新资产/高不确定性 | 快速积累样本，达到最低决策置信度 | 实时 | 事件驱动重算，轻量指标 |
| 稳定分发资产 | 日常监控，异常时深查 | T+1 批量 | 每日汇总计算，异常触发详细审计 |
| 优质加权资产 | 定期复审 + 抽检 | 周级 | 每周全量重算，结合人工抽检 |
| 降权观察资产 | 重点监控，快速验证是否恢复或下架 | 实时 | 实时更新关键指标（错误率、投诉率） |
| 长尾低曝光资产 | 批量粗略评估 | 每周或每月 | 批量计算，不参与实时管道 |

> **原则**：评估投入与资产对平台的影响成正比。高曝光资产直接影响大量用户体验，需精细评估；低曝光资产影响有限，可降低评估频率以节省资源。

### 8.3 探索代价预算与上限

探索流量可能带来负面体验，需设置代价上限：

- **失败率差上限**：探索池用户任务失败率不得高于正常池的 1.5 倍。
- **投诉率差上限**：探索池投诉率不得高于正常池的 2 倍。
- **自动熔断**：一旦探索池指标超过上限，立即缩减探索流量比例（如从 15% 降至 5%），待恢复后再逐步放开。

### 8.4 干预收益量化

每次分发干预（加权、降权、探索等）应有预期收益判断，用于指导是否值得投入资源：

```
干预净收益 ≈ (预期提升的用户成功任务数 × 单次成功价值) - (评估计算成本 + 体验损失成本 + 运营成本)
```

对于低曝光资产，即使质量分提升，带来的绝对收益有限，因此不应投入与头部资产同等的实时评估资源。反之，对于高曝光资产的微小质量变化，可能影响大量用户，值得更精细的评估。

### 8.5 评估频率自适应

- **稳定高质量资产**：降低重算频率（如每周一次），减少计算和创作者打扰。
- **波动资产**：触发式重算，异常时自动加密采样。
- **新资产**：在保护期内保持较高频率（如每日），快速建立置信度。
- **降权资产**：监控关键指标（错误率、投诉率）的实时变化，若快速恶化则立即下架。

### 8.6 成本效能监控指标

在整体监控体系中加入以下指标，持续衡量评估与干预的投入产出：

| 指标 | 说明 | 目标 |
|---|---|---|
| 评估计算资源占比 | 评估管道占用平台总计算资源的比例 | ≤ 5% |
| 探索代价比 | 探索池用户失败率 / 正常池失败率 | ≤ 1.5 |
| 人工抽检覆盖率 | 人工抽检资产数 / 总资产数 | 控制在 5% 以内 |
| 创作者申诉处理时长 | 从申诉提交到闭环的平均时间 | ≤ 3 个工作日 |
| 评估精度提升带来的收益 | 因识别低质资产减少的失败任务数 / 评估总成本 | 持续为正且递增 |
| 长尾资产提升的单位成本 | 每提升一个长尾资产进入正常分发的成本（计算+运营） | 设定上限，避免过度投入 |

## 9. 可信度保障机制

### 9.1 证据链

每个质量分必须可下钻到：

- 字段检查结果明细
- 运行日志摘要
- 用户反馈原文（脱敏）
- 样本量与置信区间
- 阈值与权重版本号

示例：

> “该资产质量分 82，处于平台前 15%。任务成功率 94%（n=120，95% CI 89%-97%），用户满意度 4.6/5。近 30 天失败率下降 3pct。低曝光但完成率高于同类均值 20%，因此建议加权分发。”

### 9.2 指标口径管理

所有指标统一埋点、统一口径，变更需发布说明。评估规则、权重、阈值支持版本化管理，可回溯任意时间点的评估逻辑。

### 9.3 评估报告

面向创作者和运营提供《资产质量评估报告》，包括：

- 综合得分与变化趋势
- 各维度得分
- 优势与短板
- 具体证据摘要
- 改进建议
- 申诉入口

### 9.4 人工抽检与校准

定期抽检：

- Top 10% 高分资产
- Bottom 10% 低分资产
- 30 天内分数异常波动资产

人工/LLM 复核评估准确性，校准框架。抽检比例需考虑运营成本，建议不超过总资产量的 5%。

### 9.5 反作弊

- 用户可信度加权
- 设备指纹与行为序列异常检测
- 样本量门槛
- 评分分布异常检测

## 10. 监控与迭代

### 10.1 业务指标

| 指标 | 目标示例 |
|---|---|
| Top 10% 资产曝光占比 | 从 70% 降至 50% 以下 |
| 基尼系数（曝光分布） | 从 0.65 降至 0.45 |
| 长尾资产（曝光 < 100/月）月活跃数 | 提升 30% |
| 新资产 30 天内获得有效样本的比例 | 从 20% 提升至 60% |
| 探索流量带来的高质资产发现率 | > 10% |
| 用户整体任务完成率 | 不低于探索机制上线前 |
| 用户投诉率（因推荐质量） | 不显著上升 |

### 10.2 评估体系可信度指标

- 质量分与真实业务结果的相关性（如高分资产留存/完成率确实更高）
- 评估覆盖率：目标 100% 在用资产
- 申诉率：目标 < 5%
- 人工抽检一致率：目标 > 90%
- 置信度覆盖率：目标 80% 资产达到置信度 ≥ 0.6

### 10.3 成本效能指标

- 评估计算资源占比 ≤ 5%
- 探索代价比 ≤ 1.5
- 人工抽检覆盖率 ≤ 5%
- 申诉处理时长 ≤ 3 个工作日
- 长尾资产提升的单位成本在预算内

### 10.4 A/B 实验与调优

通过 A/B 实验验证不同探索比例、保护期时长、加权系数、评估频率对业务指标和成本指标的影响，逐步调优。评估框架自身版本化迭代。

## 11. 实施路径

### 阶段一：MVP 基础版（低成本起步）

- 接入资产元数据、运行日志、用户评分
- 计算静态质量 + 基础用户体验分（批量处理，T+1）
- 输出质量分与简单报告
- 先用于人工审核辅助
- **成本控制**：仅覆盖核心资产，计算资源占用 < 2%

### 阶段二：动态化与分级（引入实时关键路径）

- 接入实时行为数据（仅高曝光资产走实时管道）
- 实现动态质量分、置信度、时间衰减
- 上线分级阈值与推荐加权/降权
- 支持冷启动探索流量
- **成本控制**：实时评估仅覆盖前 20% 高曝光资产，其余批量评估

### 阶段三：场景化与反马太（扩展覆盖面）

- 实现分场景质量分（离线计算场景矩阵）
- 引入长尾潜力识别与多样性加权
- 上线创作者申诉与人工抽检闭环
- 建立反作弊体系
- **成本控制**：场景分按需计算，设置探索预算上限并监控代价

### 阶段四：自动化闭环与成本调优

- 评估规则与推荐策略联动自动化
- 支持 A/B 实验验证评估框架效果
- 根据成本效能数据动态调整评估频率、探索比例、抽检比例
- 建立成本效能看板，持续优化资源分配

## 12. 总结

本框架的核心是将**可信多维度质量评估**、**动态反马太分发干预**与**成本效能权衡**三者结合，形成一个可持续运转的闭环：

- **评估层**回答“这个资产好不好、好在哪、是否可信”，并根据资产重要性分层投入评估资源。
- **干预层**回答“基于当前质量和生态状态，这个资产应该获得多少曝光、如何分发”，同时控制探索与干预的代价。
- **反馈层**通过真实用户行为持续更新评估，形成动态平衡。
- **成本层**确保评估与干预的投入与资产影响成正比，避免过度评估和过度干预。

最终目标是让平台的分发决策从“谁热推谁”转向“谁有价值、谁匹配需求、谁值得被验证”，在保证用户体验和生态健康的同时，以合理的成本实现可持续运营。
